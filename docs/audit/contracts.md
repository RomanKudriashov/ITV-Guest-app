# Контракты против кода

18 документов-контрактов против 168 путей API. Аудит только читал: расхождения записаны, не
исправлены.

**Главная цифра:** на контракты ссылаются **5 файлов тестов из 74**. Это значит, что контракт
может разъехаться с кодом, и прогон этого не заметит — расхождение обнаружит тот, кто будет писать
клиента по документу.

## 1. Покрытие

| | Сколько |
|---|---|
| Контрактов | 18 |
| Путей в API | 168 |
| Путей, упомянутых хотя бы одним контрактом | 97 |

| Путей, описанных в контракте, но отсутствующих в API | 6 (после отсева ложных совпадений) |

Метод: из контрактов извлечены все строки вида `/api/...`, `/cms/...`, `/guest/...` и сопоставлены
с путями OpenAPI после нормализации параметров (`{id}` → `{}`). Метод грубый: он видит путь, а не
поля и коды ошибок. Полей и кодов не сверял никто — см. §4.

## 4. Чего этот аудит НЕ проверял

Сверялись **адреса**. Не сверялись:

- **поля запросов и ответов** — контракт может называть поле `title`, а код отдавать `name`;
- **коды ошибок** — 422 против 400, `confirm_mismatch` против `invalid`;
- **обязательность** — контракт говорит «обязательное», схема допускает `null`.

Это сверка на порядок дороже: нужен разбор таблиц полей в 18 документах против схем OpenAPI.
Автоматизируемо: у нас есть машинная схема (`api.get_openapi_schema()`), и сверка «поля из
контракта существуют в схеме» пишется сторожем. Пока такого сторожа нет.

## 5. Документы, помеченные как расходящиеся с реальностью

### `docs/grms/iridi-probe.md` — помечен, и правильно

Документ прозвона сам говорит: ТЗ §7 требует GET с телом, а сервер одинаково принимает POST, и все
инвентаризационные прогоны сделаны POST'ом. В нём же предложение зафиксировать POST в контракте.
**Предложение не выполнено:** `grms/contracts/backend-connector.md` по-прежнему описывает метод по
ТЗ, а код ходит POST.

### Проверка на документы того же класса

Искал пометки «устарело», «расходится», «не соответствует» по всему `docs/` — **других таких
пометок нет**. Это не значит, что расхождений нет: значит, что их никто не пометил. Найденные в
§2 шесть расхождений не помечены нигде.

### Ссылки между документами

Проверил все ссылки вида `docs/*.md` внутри документации: **битых ссылок нет**, кроме
`module-registry-api-contract.md` из теста (§1).

## 6. Что с этим делать — по убыванию отдачи

Аудит ничего не менял; список — предложения, не сделанная работа.

1. **Сторож «путь есть в API — есть в контракте»**: сравнить OpenAPI со списком путей из
   контрактов и краснеть на новом неописанном пути. Дешевле всего и ловит главное — расползание.
2. **Пометить шесть найденных расхождений прямо в документах** (§2), чтобы читающий не написал
   клиента по несуществующему адресу.
3. **Закрыть контрактом платформенную консоль и CMS GRMS** — 43 пути из 71.
4. **Сверка полей** — сторож «каждое поле из таблицы контракта есть в схеме». Дороже, но именно
   поля разъезжаются молча.
