# Автоперевод витрины

Пункт 32 заказчика. Механизм построен **целиком, кроме самого вызова модели**:
очередь, отчёт, учёт расхода, защита ручной правки, правило имён собственных и
честный счётчик охвата. Модели у нас нет — и экран об этом говорит прямо.

## Почему без модели поля остаются пустыми

Соблазн был: положить в английский ключ транслитерацию или копию русской
строки, чтобы «было заполнено». Так делать нельзя. Заполненное поле уезжает в
публикацию и становится витриной отеля; отличить заглушку от настоящего
перевода снаружи невозможно, и узнают о ней от гостя. На превью бренда мы это
уже проходили.

Поэтому без модели:

* кнопка запуска **выключена** и подписана «Не подключён»;
* `POST /cms/translate/runs` отвечает `409 translation_not_connected`
  и текстом «Автоперевод пока не подключён»;
* ни один символ в переводимые поля не записывается.

Работает при этом всё остальное — и это половина пользы: отель видит дыры и
закрывает их руками.

## Счётчик охвата

«Английский: 296 из 815». Два правила, без которых число было бы ложью:

1. **Знаменатель — не «все поля», а те, где есть текст на языке отеля.**
   Считать «из семидесяти» по пустым строкам бессмысленно.
2. **Заполненным считается текст НА ЭТОМ ЯЗЫКЕ, а не любой текст в ключе.**
   Русская строка под ключом `en` — не перевод: гость увидит кириллицу в
   английской витрине, а отчёт скажет «всё готово». Такие значения считаются
   отдельной колонкой «похоже на чужой язык».

Язык узнаётся по письменности (`apps/translate/services/coverage.py`): у
арабского и китайского должна быть своя, у английского — просто не должно быть
кириллицы. **Исключение — имена собственные:** «Sakura» под ключом `ar`
написано латиницей намеренно.

На демо-стенде «Кристалл» подозрительных сейчас ноль из 815 — сид кладёт
переводы аккуратно. Колонка сторожит не сид, а ручной ввод в CMS.

## Что переводим

Только то, что читает гость. Список — один на весь механизм,
`apps/translate/fields.py`, 23 поля в десяти группах:

| Группа | Поля |
|---|---|
| заведения | название и подпись заведения |
| разделы | название и описание раздела |
| позиции | название, описание, текст инфо-страницы, характеристики (имя и значение) |
| модификаторы | группа модификаторов, вариант |
| заявки | подпись поля заявки и подсказка |
| метки | метка позиции |
| справочники | аллергены, диетические маркеры |
| места | место получения и уточнение |
| статусы | статус заказа и его название при самовывозе |
| управление номером | зона, элемент, подсказка элемента |

**Что осталось снаружи и почему** (список собран сверкой со всеми переводимыми
полями проекта, а не на глаз):

| Поле | Почему не переводим |
|---|---|
| `hotels.Hotel.name`, `.city` | имя собственное и справочник геокодера: город приезжает переведённым (см. `weather.md`) |
| `hotels.ExecutionPoint.title` | «кухня», «бар» — читает смена, не гость |
| `hotels.RoomCategory.title` | живёт только в CMS: правила и отчёты |
| `grms.RoomType.title` | конфигурация номера, гостю не показывается |
| `hotels.OnboardingTemplate`, `hotels.SystemDictionaryEntry` | платформенные справочники, отель их не правит |
| `orders.OrderItem.title_snapshot` | снимок заказа — историческая правда, менять её задним числом нельзя никогда |
| `media.MediaAsset.alt` | поле есть, но витрина его пока не отдаёт: переводить нечего, пока некому читать |

## Правка человека сильнее машины

Повторный автоперевод **не затирает** исправленное руками. В самом поле лежит
строка, и по ней не видно, кто её написал, — поэтому у каждого машинного
значения есть отметка (`translate_mark`) с отпечатком того, что записала
машина. Порядок решений по каждому значению:

1. исходника нет → переводить нечего;
2. значение есть, но отпечаток не совпал → **писал человек**, не трогаем;
3. отпечаток совпал и исходник не менялся → уже переведено, второй раз не платим;
4. строка — только имя собственное → переносим как есть, модель не зовём;
5. иначе зовём модель.

Исходник переписали — перевод устарел, и обновить его не значит затереть: в
отметке лежит и отпечаток исходника.

## Имена собственные

Правило **одно** на сид и на автоперевод, живёт в
`apps/translate/proper_nouns.py`. Родом оно из реестра демо-переводов
(`apps/hotels/seed_translations.py`): «Кристалл», «Панорама», «Сакура»,
«Марина», «Лагуна», «Талассо», «Люмен», «Азур» в арабском и китайском остаются
латиницей — так их пишут на вывеске и в картах. Переводится всё вокруг имени:
«ресторан», «бар», «СПА».

Отель пополняет список своими именами:

```json
hotel.settings = {"translation": {"keep": ["Витязь"]}}
```

Строка, состоящая из одного охраняемого слова, переносится без вызова модели.
Имя внутри фразы уезжает модели отдельным списком `keep` — чтобы она его не
переводила.

## Расход

Считается на каждый удачный вызов: `translate_usage` — вызовы и символы по
месяцам **каждого отеля**. Без этого один большой каталог съедает бюджет флота,
и узнают об этом по счёту. Видно в CMS: «2026-09 — вызовов 41, символов 1 208».

## Как подключить модель

Одна дверь, `apps/translate/providers.py`. Нужен класс с тремя вещами:

```python
class MyProvider:
    name = "my-model"
    connected = True

    def translate(self, request: TranslationRequest) -> str:
        # request.text, request.source, request.target, request.keep
        ...
```

и строка в окружении:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `TRANSLATION_PROVIDER` | `none` | Путь к классу через точку. `none` = «не подключено», и механизм честно об этом говорит |

Больше править нечего: очередь, отчёт, отметки, расход и охват уже на месте.

## Прогон

`POST /cms/translate/runs` ставит работу в очередь (`TranslationRun`,
статус `queued`) и отдаёт её воркеру **после фиксации транзакции** — иначе
воркер не найдёт строку. Каталог отеля — тысячи значений, держать оператора на
открытой вкладке незачем.

В отчёте прогона: переведено, пропущено, ошибок, символов, причины пропусков
по строкам («правка человека», «уже переведено машиной», «имя собственное»,
«Автоперевод пока не подключён») и до 50 строк ошибок модели. Сломавшаяся
модель прогон не останавливает: строка идёт в отчёт, работа продолжается.

## Адреса

| Адрес | Что делает |
|---|---|
| `GET /cms/translate/coverage` | охват по языкам и группам, состояние провайдера |
| `POST /cms/translate/runs` | поставить прогон в очередь |
| `GET /cms/translate/runs` | последние 20 прогонов |
| `GET /cms/translate/runs/{id}` | отчёт прогона |
| `GET /cms/translate/usage` | расход по месяцам |

Экран — CMS → Настройки → «Переводы витрины».
