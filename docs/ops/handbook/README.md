## Три правила, вокруг которых собрана вся книга

**Успешно выполненная команда ничего не доказывает.** Доказательство — файл,
прочитанный внутри контейнера, и действие, выполненное после. Отсюда вся глава
о выкатке.

**Ноль строк вместо ошибки.** Вне тенанта роль приложения не падает — она не
видит ничего. Data-миграция «успешно» не делает ничего, платформенная выдача
приходит пустой, восстановленная база выглядит рабочей. Это самый дорогой класс
отказов, и он выглядит как зелёный прогон.

**Состояние снимается до перезапуска.** Перезапуск лечит симптом и стирает
причину; отказ вернётся, а разбор начнётся с нуля.

## Сторожа

Книга не должна врать дольше одного прогона, поэтому фактические утверждения
проверяются машинно:

```bash
cd frontend && node scripts/check-docs.mjs        # адреса экранов, переменные окружения
docker compose exec -T backend python -m pytest tests/test_docs_guard.py
```

Первый входит в `npm run build`. Проверяется то, у чего есть источник правды в
коде: перечисления модулей, ролей, тарифов, видов групп и исходов публикации;
существование команд `manage.py`; адреса экранов против маршрутизатора;
переменные окружения против образцов. Смысл не проверяется и проверяться не
будет — сторож, который краснеет на переформулировке, выключают первым.

Перечисления в тексте помечаются так:

```
<!-- check:modules -->
| `room_control` | управление номером |
<!-- /check -->
```

Внутри блока требуется **точное совпадение множеств**: забытое в книге врёт так
же, как выдуманное.
