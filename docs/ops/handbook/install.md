# Установка с нуля

Читатель — тот, кто ставит систему на чистый сервер. Порядок здесь важен:
почти каждый шаг зависит от предыдущего, а два места ломаются молча, и о них
сказано прямо в тексте, а не в конце.

Термины — в [глоссарии](../../glossary.md). Схема адресов — в
[addressing.md](../../addressing.md): её стоит прочитать до установки, потому
что домен задаётся один раз и в двух местах сразу.

---

## Что понадобится

| | Минимум | Почему столько |
|---|---|---|
| Ядер | 2 | четыре контейнера приложения плюс база |
| Памяти | 4 ГБ | Postgres, Redis, MinIO и четыре процесса Python |
| Диска | 40 ГБ | образы, база, снимки, кэш сборки |
| ОС | Linux с Docker и Docker Compose v2 | всё живёт в контейнерах |

Наружу открываются **только 80 и 443**. Postgres, Redis и MinIO портов не
публикуют — они доступны лишь внутри сети compose. Это не рекомендация: в
`docker-compose.prod.yml` у них нет секции `ports`, и добавлять её не нужно.

**Домен.** Нужен настоящий домен с возможностью завести поддомены: отель
адресуется поддоменом (`crystal.example.com`). До появления домена стенд может
жить на `sslip.io` — это внешний сервис, который отдаёт IP, зашитый в имя.
Сертификат на голый IP выпустить нельзя, а без поддоменов схема адресов не
собирается вовсе.

---

## 1. Код и окружение

```bash
git clone <репозиторий> ITV-Guest-app
cd ITV-Guest-app
cp .env.prod.example .env.prod
```

`.env.prod` **не коммитится** и живёт только на сервере. Дальше по тексту
книга называет переменные по имени и никогда — по значению.

### Что задать обязательно

<!-- check:env -->
| Переменная | Что это | Если не задать |
|---|---|---|
| `APP_DOMAIN` | базовый домен платформы | отель не найдётся по поддомену, консоль откроется где угодно |
| `DJANGO_SECRET_KEY` | ключ подписи Django | значение по умолчанию небезопасно |
| `JWT_SECRET` | ключ токенов персонала и платформы | то же |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | база приложения | контейнер не поднимется |
| `POSTGRES_PLATFORM_USER`, `POSTGRES_PLATFORM_PASSWORD` | вторая роль Postgres, с атрибутом BYPASSRLS | платформенные выдачи вернут ноль строк |
| `POSTGRES_SUPERUSER`, `POSTGRES_SUPERUSER_PASSWORD` | роль для миграций и создания ролей | миграции не применятся |
| `MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD` | доступ к хранилищу картинок | медиа не сохранится |
| `MINIO_PUBLIC_ENDPOINT` | адрес хранилища для браузера гостя | картинки не откроются у гостя |
| `DJANGO_DEBUG` | режим отладки | **обязан быть `0`**: в дебаге принимается подмена тенанта заголовком |
| `GUEST_APP_PUBLIC_SCHEME` | схема публичных ссылок | QR-коды закодируют `http` вместо `https` |
<!-- /check -->

Владельца платформы в этом списке нет намеренно: он заводится командой
(шаг 4), а не переменной. На нашем стенде почта и пароль владельца дописаны в
`.env.prod` руками — как заметка, где их искать; система их не читает.

### Что стоит знать про остальные

<!-- check:env -->
| Переменная | Умолчание | Когда трогать |
|---|---|---|
| `GUEST_SESSION_TTL_HOURS` | 12 | срок гостевой сессии |
| `GUEST_APP_RESERVED_SUBDOMAINS` | `www,api,admin,platform,static,media` | имена, которые нельзя отдать отелю |
| `CACHE_URL` | Redis, база 4 | кэш: погода, схлопывание чтений оборудования, счётчик попыток PIN |
| `REDIS_URL`, `CELERY_BROKER_URL`, `CELERY_RESULT_BACKEND`, `CHANNELS_REDIS_URL` | Redis, базы 0–3 | разнесены по базам намеренно: очередь, результаты и каналы не должны мешать друг другу |
| `WEATHER_PROVIDER`, `WEATHER_API_URL` | `open-meteo` | единственный внешний источник, к которому ходит бэкенд |
| `WEATHER_REFRESH_SECONDS`, `WEATHER_FRESH_SECONDS` | 1200 / 2700 | как часто спрашиваем погоду и сколько она считается свежей |
| `NOTIFICATIONS_ENABLED` | включено | глушит уведомления целиком |
| `TELEGRAM_API_URL` | боевой адрес | подменяется в тестах |
| `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`, `EMAIL_USE_TLS`, `DEFAULT_FROM_EMAIL` | локальный SMTP | без почты пароль администратору отеля отправить нечем — заведение упадёт с внятной ошибкой, а не молча |
| `PLATFORM_REQUIRE_2FA` | выключено | требовать второй фактор у нашей команды |
| `PLATFORM_IP_ALLOWLIST` | пусто | пускать в консоль только с этих сетей |
| `API_VERSION`, `API_LEGACY_SUNSET` | `v1`, пусто | версия API и дата отключения старых путей |
| `APP_LINKS_ENABLED`, `IOS_APP_ID`, `ANDROID_PACKAGE` | выключено | связь с мобильным приложением; включать, только когда приложение существует |
| `PAYMENT_ADAPTER`, `PMS_ADAPTER` | «нет» | заглушки под интеграции: честно отвечают «недоступно», а не притворяются |
| `SEED_ON_START`, `SEED_ARGS` | включено, аргументы пусты | сид демо-отеля на старте — см. предупреждение ниже |
| `ITV_CONNECTOR_KEY` | пусто | ключ коннектора, если он стоит на этом же сервере |
<!-- /check -->

Полный список — `.env.prod.example`; он же единственный источник правды о том,
какие переменные система вообще читает. Переменная, которой там нет, ничего не
включает, сколько её ни задавай. Так, PLATFORM_ADMIN_EMAIL и
PLATFORM_ADMIN_PASSWORD выглядят как настройка, но не читаются ничем; число
процессов приложения и авто-перезагрузка (WEB_CONCURRENCY, UVICORN_RELOAD)
заданы прямо в `docker-compose.prod.yml`, и в `.env.prod` их искать незачем.

> **Сид на боевой установке.** Образец идёт с `SEED_ON_START=1`: это стендовое
> умолчание, и оно заводит демо-отель «Кристалл», чтобы поддомен резолвился
> сразу. Настоящему клиенту чужой демо-отель во флоте не нужен — ставьте
> `SEED_ON_START=0` **до первого запуска**. После него отель придётся удалять
> руками.

## 2. Первый запуск

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build
```

Поднимутся десять контейнеров: `postgres`, `redis`, `minio`, `mailpit`,
`backend`, `worker`, `beat`, `nginx`, `iridi-emulator`, `connector`.

### Включить режим HTTP — **иначе всё отдаёт 404**

```bash
./infra/nginx/bootstrap-http.sh
docker compose -f docker-compose.prod.yml --env-file .env.prod restart nginx
```

Пропустить этот шаг нельзя, и пропускается он легче всего, потому что
контейнеры при этом поднимаются **все десять и здоровыми**. У nginx две
взаимоисключающие ветки: «есть сертификат — редирект на HTTPS» и «нет
сертификата — приложение прямо на 80-м». Вторая кладётся этим скриптом, и до
него не подключена ни одна: nginx отдаёт свою страницу 404 на **любой** адрес,
включая `/api/v1/health`.

Как это выглядит в логе — и как отличить от настоящей поломки:

```
[error] open() "/etc/nginx/html/admin" failed (2: No such file or directory)
```

Путь `/etc/nginx/html/…` — это дефолтный корень nginx. Значит запрос до
приложения не дошёл вовсе, и искать в бэкенде нечего.

Бэкенд при старте сам применит миграции и создаст роль платформы. Проверить:

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod ps
docker compose -f docker-compose.prod.yml --env-file .env.prod \
  exec -T backend python manage.py showmigrations | grep '\[ \]'
```

Вторая команда должна не вывести ничего: `[ ]` — метка непримененной миграции.
Искать надо именно её, а не отсутствие `[X]`: `showmigrations` печатает ещё и
названия приложений отдельными строками, и отбор «всё, где нет `[X]`» всегда
выдаёт тринадцать строк на исправной системе.

> **Ломается молча №1.** В прод-файле эмулятор iRidi и коннектор поднимаются
> всегда, а в файле для разработки — только под профилем `grms`
> (`docker compose --profile grms up -d`). Отсюда обычная путаница: на своей
> машине управление номером «не работает», хотя оно просто не запущено. Первое,
> что надо посмотреть, — поднят ли контейнер, а не логи бэкенда.

### Коннектор на новой установке кричит — и это нормально

Сразу после первого запуска в его логе идёт по строке на каждую попытку:

```
ERROR itv.connector конфиг не загружен: не найден ключ узла:
      ни node_key_file, ни ITV_CONNECTOR_KEY
```

Ключ выдаётся в консоли и до неё не существует — значит на чистой установке
коннектору подключаться нечем. Контейнер при этом **`Restarting`**: процесс
падает, `restart: unless-stopped` поднимает его снова, и так до появления
ключа. То есть в `ps` сразу после установки одна служба из десяти не `running`
— и это ожидаемо, а не поломка.

Пока управление номером не заводили, эти строки читать не нужно; заводить —
по [connector.md](connector.md). Если управления номером у отеля не будет
вовсе, коннектор проще остановить: `docker compose … stop connector`.

**И до того, как заводить: в `connector/config.stand.json` зашит адрес нашего
стенда.** Прод-файл монтирует именно его. Оставленный как есть, коннектор
новой установки стучится в чужую систему и получает `403` в петле. Адрес
меняется до первого запуска коннектора, а не после.

## 3. Сертификат и HTTPS

Пока сертификата нет, nginx отвечает по HTTP. Выпуск:

```bash
APP_DOMAIN=example.com ./infra/nginx/enable-tls.sh admin@example.com
docker compose -f docker-compose.prod.yml --env-file .env.prod restart nginx
```

Скрипт идемпотентен: certbot сам решит, продлевать или нет. Выпуск идёт
методом `webroot` — nginx при этом **остаётся поднятым**; гасить его ради
продления значит ронять систему каждые три месяца.

**Сертификат выписывается на список имён:** базовый домен плюс по одному на
каждый отель. Добавился отель — имя дописывается в скрипт, и он гоняется
заново. На настоящем домене это снимается wildcard-сертификатом по DNS-01, и
тогда новый отель не требует ничего; на `sslip.io` wildcard не выпустить.

Проверка:

```bash
echo | openssl s_client -connect example.com:443 -servername example.com 2>/dev/null \
  | openssl x509 -noout -dates -text | grep -A2 "Subject Alternative Name"
```

В списке имён должны быть базовый домен и все поддомены отелей.

## 4. Владелец платформы

Первый владелец не появляется сам — его заводят командой:

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod \
  exec -T backend python manage.py create_platform_admin \
  --email=owner@example.com --password='…'
```

Команда идемпотентна: повторный вызов с тем же адресом меняет пароль, а не
плодит вторую учётку. Заводится она **платформенной ролью**, потому что у
платформенного пользователя нет отеля, а роль приложения таких строк не видит:
под обычной ролью команда «отработала бы успешно» и не создала ничего.

Вход — `/admin` на **корневом** адресе.

Проверка, что консоль отвечает и что она отвечает **только там, где должна**:

```bash
curl -sS -o /dev/null -w '%{http_code}\n' https://example.com/admin
curl -sS -X POST https://crystal.example.com/api/v1/platform/auth/login \
     -H 'Content-Type: application/json' -d '{"email":"…","password":"…"}'
```

Второй запрос обязан вернуть **404 `platform_wrong_host`**: консоль живёт на
корне, и с адреса отеля её нет. Если он вернул токен — домен задан неверно
(см. `APP_DOMAIN`), и мастер-ключ доступен с адреса каждого клиента.

Сразу после первого входа стоит включить второй фактор и, если у команды
статические адреса, задать `PLATFORM_IP_ALLOWLIST`.

## 5. Первый отель

Дальше — [подключение отеля](onboarding.md) целиком. Кратко, чтобы проверить
установку:

1. В консоли: **Флот → Новый отель**. Поддомен, название, почта администратора.
2. Пароль администратора уходит **письмом** — в интерфейсе он не показывается.
   Без настроенной почты заведение упадёт с внятной ошибкой; это не поломка, а
   отказ, и лечится он настройкой SMTP, а не повтором.
3. Открыть `https://<поддомен>.example.com/` — должна открыться витрина.
4. Открыть `https://<поддомен>.example.com/admin` — панель отеля.

> **Ломается молча №2.** Демо-конфигурация управления номером сеется только с
> флагом: `manage.py seed_demo_hotel --with-room-control`. Без него экран
> номера открывается **пустым** — ни одного контрола, — и выглядит это как
> поломка фронта. Боевому отелю флаг не нужен; он нужен демо-стенду.

## 6. Проверка установки

```bash
curl -sS https://example.com/api/v1/health
```

Проверяет базу, Redis и MinIO. Дальше — глазами, по одному экрану на каждую
поверхность:

| Что открыть | Что должно быть видно |
|---|---|
| `https://example.com/` | лендинг платформы |
| `https://example.com/admin` | вход в консоль |
| `https://<отель>.example.com/` | витрина гостя, поле ввода номера |
| `https://<отель>.example.com/admin` | вход в панель отеля |
| `https://<отель>.example.com/tracker` | доска исполнителя (после входа сотрудника) |

Если корень показывает не лендинг, а поле ввода номера комнаты — фронт собран
без `APP_DOMAIN`. Это сборочный аргумент образа nginx, а не переменная
времени выполнения: перезапуск не поможет, нужна пересборка (см.
[выкатку](deploy.md)).
