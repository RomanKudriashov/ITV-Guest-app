# Что это за система

Гостевое веб-приложение отеля: гость открывает его по QR-коду в номере, заказывает еду и услуги,
переписывается с персоналом, управляет оборудованием номера. Вокруг него — панель управления для
персонала и отеля и консоль платформы, которая заводит отели.

Документ отвечает на вопрос «где что лежит и почему именно так». Он НЕ пересказывает код: там,
где утверждение проверяется прогоном, назван тест.

---

## Четыре роли, четыре поверхности

| Роль | Что делает | Как входит | Адреса |
|---|---|---|---|
| **Гость** | смотрит витрину, заказывает, переписывается, управляет номером | QR-код → сессия по номеру комнаты, без пароля | `/api/v1/guest/*` (21 путь) |
| **Персонал** | ведёт заказы на трекере, отвечает в чате | логин сотрудника, привязка к точке исполнения | `/api/v1/tracker/*`, `/api/v1/staff/*` (11) |
| **Администратор отеля** | наполняет витрину, настраивает отель, собирает интерфейс номера | логин, роль в отеле | `/api/v1/cms/*` (101) |
| **Платформа** | заводит отели, тарифы, флот, коннекторы | отдельный логин владельца платформы | `/api/v1/platform/*` (31) |

Всего 168 путей. Разделение не косметическое: у каждой поверхности своя авторизация, свой набор
прав и свой контракт. Гость технических параметров не получает вовсе (ТЗ §13) — ни имени
устройства, ни канала, ни адреса коннектора.

## Из чего состоит

```
Гостевой браузер (React + MUI, Vite)
        │  HTTP + WebSocket
Центральный backend (Django 5 + django-ninja, Postgres с RLS, Redis, Celery)
        │  исходящее соединение, инициирует коннектор
Local Connector (отдельный сервис на объекте)
        │  HTTP во внутренней сети
iRidi HTTP-сервер → драйверы → GRMS → оборудование номера
```

Отдельно: MinIO — объектное хранилище картинок; провайдер погоды (Open-Meteo) — единственный
внешний источник, к которому ходит backend сам.

---

## Многотенантность: один экземпляр, много отелей

Данные отелей лежат в одних таблицах и разделяются **на уровне базы** — политиками RLS
PostgreSQL по `app.current_hotel`. Прикладной код не может «забыть» отфильтровать: строку чужого
отеля он не увидит физически.

- Контекст ставится `tenant_context(hotel)`; вне контекста тенантные таблицы не читаются.
- Платформенные операции идут через `platform_scope()` — роль с BYPASSRLS.
- Проверяется: `tests/core/services/test_rls_coverage.py`, `tests/core/services/test_tenant_isolation.py`.

**Известная особенность прогона:** роли с BYPASSRLS в тестовой базе нет, поэтому код, читающий
«поверх всех отелей», в прогоне молча видит ноль строк. Об это спотыкались трижды —
см. `docs/decisions.md`, решение «чтение только в контексте тенанта».

## Как режутся домены

Один домен — одно приложение Django. Внутри приложения три слоя, и граница между ними
проверяется прогоном, а не договорённостью.

```
apps/{домен}/
    models/      строки и инварианты
    services/    вся работа с ORM и бизнес-логика
    schemas/     тела запросов и ответов
    api/
        guest/ cms/ staff/ platform/ onprem/    вьюхи по поверхностям
        router.py                               сборка
```

| Домен | О чём | Крупные части |
|---|---|---|
| `accounts` | гости, сотрудники, роли, уровни доверия | сессия гостя, логин персонала |
| `catalog` | витрина: разделы, позиции, модификаторы, поиск, главная | showcase, availability, slots |
| `orders` | заказы, статусы, трекеры, коммерция | расчёт сумм, типизированные трекеры |
| `chat` | переписка гостя и персонала | треды, непрочитанное |
| `reviews` | отзывы | |
| `hotels` | сам отель: бренд, номера, локации, расписания, тарифы, офбординг | провижининг, платформенная консоль |
| `grms` | управление номером | транспорт, адаптер iRidi, конфигуратор, план |
| `media` | картинки | пайплайн MinIO + Pillow, ревизор хранилища |
| `notifications` | эскалация и каналы уведомлений | log/email/telegram |
| `analytics` | отчёты | выгрузки |
| `integrations` | швы наружу: PMS, платежи | пока только заглушки `Null*` |
| `core` | контекст тенанта, ошибки, аудит | |
| `realtime` | WebSocket-каналы | |

**`api/` в корне backend — только сборка роутеров, 102 строки.** Вьюх там нет: это результат
переноса раскладки (партии 0–7, `docs/refactor/structure-analysis.md`).

Тесты зеркалят ту же раскладку: `tests/{домен}/{api,services}/`.

---

## Что охраняет раскладку

| Сторож | Что ловит |
|---|---|
| `tests/test_safety_net.py` (7 проверок) | пропажу маршрута, задачи Celery, команды; путь, объявленный в двух модулях |
| `scripts/check_views.py` | ORM во вьюхах — исключений сейчас 0 |
| `frontend/scripts/check-colors.mjs` | цвет мимо словарей |
| `frontend/scripts/check-locales.mjs` | ключ, которого нет в одном из четырёх языков |
| `e2e/tests/sticky-stack.spec.ts` | липкий слой, накрывший содержимое |
| `e2e/tests/text-overflow.spec.ts` | текст, не помещающийся в плашку |

Прогон: **840 тестов бэкенда** (6 пропускаются, см. `docs/audit/evidence.md`), **220 тестов E2E**.
Бэкенд идёт в четыре процесса, 29 минут.

## Языки

Четыре: русский, английский, арабский, китайский. Арабский — RTL, и это не только направление
текста: зеркалятся раскладки, но НЕ план номера (комната не зеркалится вместе с интерфейсом).
Полнота словарей проверяется сторожем на каждой сборке — 1790 основ ключей в каждом языке.

Контент отеля (названия блюд, города, описания) хранится переводами, а не строкой.
**Машинного перевода нет** — переводы вводит администратор.
